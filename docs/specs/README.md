# Specifications

This directory is the source of truth for behavior before implementation.

Each feature starts as a focused Markdown specification containing:

- context and user-visible goal;
- functional requirements and explicit non-goals;
- observable acceptance criteria;
- protocol or model changes;
- failure, stale-data, accessibility, and security behavior;
- verification strategy.

Use one file per feature, named `NNN-short-title.md`. Keep implementation details out unless they are architectural constraints.
